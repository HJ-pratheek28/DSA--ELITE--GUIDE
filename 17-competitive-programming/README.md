# 17 — Competitive Programming

**Goal:** convert algorithmic knowledge into reliable performance under time constraints.

## Contest workflow
1. Scan all problems and classify by likely topic / difficulty.
2. Secure straightforward problems first.
3. Read constraints before choosing an approach.
4. Keep a time budget; move on when progress stalls.
5. Test boundaries before submitting.
6. After the contest, upsolve every problem you could not solve.
7. Record the missing insight and re-solve later without editorial.

## Practice modes
- Topic practice: build a specific skill.
- Mixed practice: choose the technique yourself.
- Virtual contest: practise timing and decision-making.
- Upsolving: turn missed problems into durable knowledge.
- Implementation drill: improve speed and reduce bugs.

## Suggested platforms
- [Codeforces](https://codeforces.com/)
- [AtCoder](https://atcoder.jp/)
- [CSES](https://cses.fi/problemset/)
- [USACO Guide](https://usaco.guide/)

## Rating review
Review multiple contests, not a single result. Track:
- Problems solved independently
- Time to first accepted solution
- Wrong submissions and their causes
- Upsolved problems
- Topic gaps
- Performance under pressure

## Exit standard
A sustainable contest routine, reliable implementation habits and evidence of improvement across a sequence of contests.
