# Quality Standards

A repository becomes useful when its content is accurate, navigable and reproducible.

## Learning-note standard
Every module should contain:
- Learning objectives and prerequisites
- A concept map and ordered topic sequence
- Intuition plus precise definitions
- At least one worked example
- Correctness reasoning and complexity
- Common misconceptions and edge cases
- Curated practice ladder with original links
- Exit test and further resources

## Solution standard
Every non-trivial solution should include:
- Original problem URL and identifier
- Constraints and approach
- Key observation / invariant
- Correctness argument
- Time and auxiliary-space complexity
- Compilable C++20 source
- Edge-case notes

## Code standard
- Use descriptive names and consistent formatting.
- Avoid undefined behaviour, signed overflow and invalid iterator use.
- Prefer standard library components when they improve clarity.
- State assumptions about input and indexing.
- Test boundary cases, not only sample cases.
- Do not claim a solution is accepted unless it was actually tested on the target platform.

## Curation standard
- Link to original problem statements.
- Order problems by prerequisite and difficulty.
- Avoid huge unfiltered problem dumps.
- Include a reason each problem belongs in the ladder.
- Check links and remove duplicates periodically.

## Completion standard
A topic is mastered only after independent explanation, implementation, proof and successful transfer to unseen problems.
